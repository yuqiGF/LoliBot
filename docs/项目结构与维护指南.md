# 项目结构与维护指南

这份文档用于说明 LoliBot 的内部结构和维护边界，后续添加功能时可以按这里的规则放置代码。

## 分层原则

### 1. plugin：QQ 消息入口

`com.bot.plugin` 只负责三件事：

- 使用 Shiro 注解匹配群聊或私聊消息。
- 解析用户输入，调用 service / utils 完成业务。
- 将结果包装成 QQ 消息并发送。

插件里尽量不要直接写 HTTP 请求、文件渲染、复杂解析逻辑。否则插件会变得很长，也不方便单独测试。

### 2. service：AI 服务接口

`com.bot.service` 用于定义 LangChain4j AI 服务接口，例如 `DashScopeService`。

Prompt、记忆、RAG、护轨等模型能力由 `config` 组装，插件只调用接口，不关心模型内部细节。

### 3. utils.ai：AI 外部接口

`com.bot.utils.ai` 放非 LangChain4j 管理的 AI 客户端，例如：

- `DeepSeekClient`：DeepSeek HTTP API。
- `VideoGenerator`：通义万相视频生成。

这些类应该由 Spring 托管并通过配置注入 API Key，不要在插件里 `new`，否则配置值无法注入。

### 4. utils.crawler：外部数据抓取

`com.bot.utils.crawler` 放萌娘百科、Bangumi、WakaTime 等外部数据获取逻辑。

注意事项：

- 网络请求要有超时和失败兜底。
- 不要在这里直接发送 QQ 消息。
- 如果接口依赖当前网络环境，插件层需要给用户明确失败提示。

### 5. utils.common：跨功能通用工具

`com.bot.utils.common` 放多个功能都会用到的小工具，例如：

- `MessageTextUtils`：统一处理 CQ 码、提取图片 URL。
- `BotCommandUtils`：统一判断跨插件共享的命令意图。
- `TypstRenderUtils`：统一调用 Typst 渲染 PNG。
- `HttpClientPool`：统一 HTTP 连接池和请求配置。

### 6. game：纯游戏逻辑

`com.bot.game` 放不依赖 QQ 框架的游戏核心逻辑。

例如 `MinesweeperGame` 只负责棋盘、地雷、胜负判断和渲染文本/Typst 源码；`MinesweeperPlugin` 才负责群消息和发送图片。

## 添加新功能的建议流程

1. 先确定入口命令，例如 `xxx` 或 `@机器人 xxx`。
2. 在 `plugin` 下创建插件类，只写命令匹配和消息发送。
3. 如果需要外部 API，新建 `utils.ai` 或 `utils.crawler` 客户端。
4. 如果需要配置项，先加到 `application.yml` 默认值，再加到 `application-local.example.yml` 示例。
5. 如果有多个插件会复用的逻辑，放到 `utils.common`。
6. 跑 `.\mvnw.cmd -q -DskipTests package` 确认至少能编译通过。

## 配置约定

- 新配置字段优先使用 kebab-case，例如 `api-key`。
- 需要兼容旧字段时，可以在 `@Value` 中写成 `${new-key:${old_key:}}`。
- 密钥、私有 QQ 号、私有群号不要写进公开配置。
- `application-local.yml` 只在本地存在，不提交。

## 注释约定

- 类注释说明“这个类负责什么、不负责什么”。
- 复杂方法注释说明“输入是什么、输出是什么、失败如何处理”。
- 简单 getter/setter、显而易见的赋值不需要注释。
- 中文注释要解释业务意图，不只是重复代码字面含义。

## 当前暂缓维护项

`今日新番` 依赖 Bangumi。在当前网络环境下 Bangumi 可能被拦截，因此该功能先保持现状，不作为近期优化重点。
